## Sources and implementation choices

- [Official Tetris gameplay](https://play.tetris.com/games/) describes increasing speed as levels progress; [Tetris Effect official media](https://tetriseffect.game/connected/media/) informed the framed dark-stage direction. The artwork and numeric speed curve here are original, rather than copied assets or a claim of commercial rotation/lock equivalence.
- [Mattel UNO Flip instructions](https://service.mattel.com/instruction-sheets/files/GDR44%20UNO%20Flip%5BEnglish_French_German_Spanish_Portuguese%5D%5B5LG%5D.pdf) specify different light/dark palettes. Same-color pairing is the user's requested, explicitly disclosed arcade variant, not a correction to the official rule.
- [WPA rules](https://wpapool.com/rules/) inform the existing called-eight/foul concepts. This arcade retains its disclosed differences, including no spin/jump shots and automatic break-eight spotting.
- [MDN collision techniques](https://developer.mozilla.org/en-US/docs/Games/Techniques/2D_collision_detection) and the existing fixed-step simulations inform shared collision footprints, bounded substeps, impulses and presentation interpolation. New tournament and market rules are disclosed house rules.

## Limits and publication

Production hosts remain outside this environment's allowed network destinations. Native publication receipts can verify the deployed source/bindings, but cannot substitute for production gameplay timing. Heuristic AI remains intentionally imperfect; the previously disclosed Phone template and Terra follow/mine limitations remain.

Publication follows the authorized order: GitHub exact source → GPT Site saved version/deployment → dedicated `markup-arcade` Worker. Preserve the public audience, D1 binding and both Durable Object namespaces. Native version/deployment receipts are reported only after success.
